# نُور — NOOR Store

منصة تجارة إلكترونية جزائرية متكاملة، عربية أولاً وبتصميم RTL فاخر، مبنية بـ **Next.js 15 + React 19 + TypeScript + Tailwind CSS 4**. تشمل واجهة متجر كاملة، سلة ودفع، 58 ولاية، طرق دفع COD/CIB/الذهبية، ولوحة تحكم إدارية كاملة لكل شيء.

> **جاهز للتشغيل مباشرة:** يعمل محلياً بقاعدة بيانات SQLite مدمجة (بدون أي إعداد)، ويتحوّل تلقائياً إلى PostgreSQL/Supabase عند ضبط `DATABASE_URL`.

## المزايا

### واجهة المتجر
- تصميم عربي فاخر RTL بالكامل + تبديل اللغة إلى الفرنسية (محفوظ في كوكي).
- هيدر ثابت مع شعار، تصنيفات، بحث فوري بالاقتراحات، عدّاد السلة، وقائمة جوال.
- سلايدر رئيسي، شريط ثقة، شبكة تصنيفات، أقسام: مميز، الأكثر مبيعاً، وصل حديثاً، تخفيضات.
- بطاقات منتجات كاملة: صورة، اسم، سعر DZD، سعر قبل التخفيض، نسبة الخصم، وصف قصير، توفر، نجوم/تقييمات، أزرار إضافة للسلة وعرض التفاصيل.
- صفحة منتج: معرض صور مع تكبير، مواصفات، متغيرات (لون/مقاس)، مخزون، كمية، تقييمات، منتجات مشابهة، وبيانات JSON-LD.
- سلة جانبية + صفحة سلة كاملة: تعديل الكميات، حذف، كوبونات، حفظ في `localStorage`.
- دفع كامل: الاسم، هاتف جزائري (05/06/07 + 8 أرقام)، 58 ولاية و1541 بلدية، عنوان، ملاحظات، توصيل منزل/مكتب، رسوم حسب الولاية، شحن مجاني فوق حد معيّن، COD/CIB/الذهبية، وصفحة تأكيد برقم طلب.
- تتبّع الطلب، فاتورة قابلة للطباعة، صفحات: من نحن، اتصل بنا، الأسئلة الشائعة، الشحن، الخصوصية، الشروط.
- SEO: Metadata، Open Graph، JSON-LD (Product / Breadcrumb / FAQ)، sitemap وrobots.
- متجاوب بالكامل مع حركات وانتقالات سلسة.

### لوحة التحكم
- تسجيل دخول آمن (scrypt + كوكي HttpOnly موقّع HMAC).
- لوحة إحصائيات: إجمالي المبيعات، الطلبات، المنتجات، العملاء، رسم إيرادات 6 أشهر، توزيع الحالات، أحدث الطلبات، الأكثر مبيعاً، مخزون منخفض.
- إدارة كاملة (إضافة/تعديل/حذف/تفعيل): المنتجات، التصنيفات، الطلبات، الكوبونات، التقييمات، آراء العملاء، البانرات، أسعار الشحن، الرسائل، الإعدادات.
- رفع الصور (Supabase Storage أو `/public/uploads` محلياً).
- تحديث حالة الطلب (قيد الانتظار، مؤكد، قيد التحضير، تم الشحن، تم التسليم، ملغى) وحالة الدفع.
- تصدير الطلبات CSV (بترميز UTF-8 مع BOM لدعم العربية في Excel) وطباعة الفواتير.
- بحث وتصفية وترقيم صفحات في الطلبات والمنتجات.

## التشغيل السريع

### المتطلبات
- **Node.js 22.5+** (مطلوب لدعم `node:sqlite` المدمج). يفضّل Node 22 LTS أو أحدث.
- npm 10+.

### الخطوات

```bash
# 1) تثبيت الحزم
npm install

# 2) إنشاء ملف البيئة
copy .env.example .env.local     # Windows
# cp .env.example .env.local     # macOS / Linux

# 3) (اختياري) تعديل AUTH_SECRET وبيانات المدير في .env.local

# 4) تشغيل التطوير — تنشأ قاعدة SQLite وتُزرع البيانات تلقائياً
npm run dev
```

افتح: **http://localhost:3000**

- المتجر: `/`
- لوحة التحكم: `/admin`
- تسجيل الدخول: `/admin/login`

> في أول تشغيل تُنشأ قاعدة `.data/noor.db` وتُزرع 29 منتجاً، 8 تصنيفات، 3 بانرات، آراء عملاء، كوبونات، 58 ولاية شحن، وطلبات تجريبية (يمكن تعطيل ذلك بـ `AUTO_SEED=false`).

## متغيرات البيئة

| المتغير | مطلوب | الوصف |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | نعم | رابط الموقع الكامل (بدون `/` في النهاية) للـ SEO والروابط المطلقة. |
| `AUTH_SECRET` | نعم | مفتاح طويل عشوائي لتوقيع كوكي الجلسة. |
| `ADMIN_EMAIL` | نعم | بريد المدير الأول. |
| `ADMIN_PASSWORD` | نعم | كلمة مرور المدير الأول (8+ أحرف). |
| `ADMIN_NAME` | لا | اسم المدير الظاهر. |
| `DATABASE_URL` | لا | رابط PostgreSQL/Supabase. فارغ = SQLite محلي. |
| `NEXT_PUBLIC_SUPABASE_URL` | لا | رابط مشروع Supabase (لرفع الصور). |
| `SUPABASE_SERVICE_ROLE_KEY` | لا | مفتاح الخدمة لرفع الصور (سري — لا يُعرّض للعميل). |
| `SUPABASE_STORAGE_BUCKET` | لا | اسم Bucket عام، افتراضياً `products`. |
| `AUTO_SEED` | لا | `false` لتعطيل الزرع التلقائي في الإنتاج. |

توليد مفتاح سري:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

## قاعدة البيانات

### SQLite (تطوير محلي)
- الملف: `.data/noor.db` (يُنشأ تلقائياً).
- المخطط: `database/schema.sqlite.sql` و`src/lib/schema.ts`.
- لا يحتاج أي خدمة خارجية.

### PostgreSQL / Supabase (إنتاج)
1. أنشئ مشروعاً على [Supabase](https://supabase.com).
2. نفّذ `database/supabase-schema.sql` في **SQL Editor** (يتضمن RLS).
3. انسخ Connection String (Pooler, Transaction mode) إلى `DATABASE_URL`.
4. أعد تشغيل التطبيق — سيتحول تلقائياً إلى PostgreSQL.

```env
DATABASE_URL=postgresql://postgres.xxxx:PASSWORD@aws-0-eu-central-1.pooler.supabase.com:6543/postgres
```

> التطبيق ينشئ الجداول تلقائياً أيضاً عند أول اتصال، لكن تنفيذ ملف SQL يدوياً يضمن تفعيل سياسات RLS.

### تخزين الصور
- بدون Supabase: تُحفظ الصور في `public/uploads/` وتُخدم مباشرة.
- مع Supabase: أنشئ Bucket **عاماً** باسم `products`، واضبط المتغيرات الثلاثة. عندها يرفع الـ API إلى Storage ويعيد الرابط العام.

> على Vercel نظام الملفات للقراءة فقط — **يجب** استخدام Supabase Storage في الإنتاج.

## الدفع والشحن

### طرق الدفع
- **COD (الدفع عند الاستلام):** يعمل بالكامل — الطلب يُسجّل بحالة دفع `pending` ويُدار من لوحة التحكم.
- **CIB / الذهبية:** في الوضع اليدوي يُسجّل الطلب ويُطلب من العميل انتظار التواصل. توجد حقول SATIM (Merchant ID / Terminal ID / Secret) في الإعدادات لربط بوابة الدفع لاحقاً.
- لا يتم تخزين أي بيانات بطاقات في التطبيق.

### الشحن
- 58 ولاية، سعران لكل ولاية: توصيل للمنزل وتوصيل للمكتب.
- الشحن المجاني عند تجاوز `free_shipping_threshold` (قابل للتعديل).
- البلديات مرتبطة بالولاية في نموذج الدفع.

### التحقق
- الهاتف: `^(0)(5|6|7)[0-9]{8}$`.
- الأسعار والكميات تُتحقق من جهة الخادم أيضاً، ويُعاد حساب الإجمالي في `/api/orders` (لا يُقبل إجمالي العميل).
- المخزون يُنقص عند إنشاء الطلب داخل معاملة، والكوبون يُسجّل استخدامه.

## النشر

راجع **[DEPLOYMENT.md](./DEPLOYMENT.md)** للخطوات التفصيلية (Vercel + Supabase). الملخص:

1. أنشئ قاعدة Supabase ونفّذ `database/supabase-schema.sql`.
2. أنشئ Bucket عاماً `products` وفعّل Storage API.
3. ارفع المشروع إلى GitHub واربطه بـ Vercel.
4. أضف متغيرات البيئة (`DATABASE_URL`, `AUTH_SECRET`, `ADMIN_*`, `NEXT_PUBLIC_SITE_URL`, `SUPABASE_*`).
5. اضبط `AUTO_SEED=false` بعد أول زرع، ثم انشر.
6. بدّل كلمة مرور المدير الافتراضية فوراً.

## الأمان

- كلمات مرور المدير مُخزّنة بـ **scrypt** (ملح عشوائي لكل مستخدم).
- جلسة موقّعة **HMAC-SHA256** في كوكي `HttpOnly` + `SameSite=Lax` + `Secure` في الإنتاج.
- كل Server Actions الإدارية تتحقق من الجلسة عبر `requireAdmin()`.
- استعلامات SQL بمعاملات (Parameterized) لمنع الحقن.
- التحقق من المدخلات في الواجهة والخادم، وتنقية JSON للمواصفات/المتغيرات.
- رفع الصور: قيود النوع والحجم (8MB) عبر `/api/admin/upload` المحمي.
- RLS في Supabase يمنع الوصول المباشر للجداول الحساسة بمفتاح anon.

## استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| `node:sqlite` غير موجود | استخدم Node 22.5+ (`node -v`). |
| لا تظهر المنتجات | شغّل `npm run db:seed` أو احذف `.data/` وأعد التشغيل. |
| فشل رفع الصور على Vercel | اضبط `NEXT_PUBLIC_SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` وBucket عام. |
| تسجيل الدخول لا يعمل | تحقق من `ADMIN_EMAIL`/`ADMIN_PASSWORD` ثم `npm run db:reset` (أو أنشئ الحساب من جديد). |
| خطأ اتصال PostgreSQL | شغّل `npm run db:check`؛ سيحدد السبب (مشروع محذوف/متوقف، كلمة مرور، مضيف IPv6، جدول ناقص). استخدم Pooler URL وتأكد من تنفيذ ملف SQL. |
| العربية تظهر مشوّهة في CSV | الملف يبدأ بـ BOM؛ افتحه في Excel مباشرة. |
| PowerShell يمنع npm | استخدم `cmd /c "npm run dev"` أو غيّر ExecutionPolicy. |
